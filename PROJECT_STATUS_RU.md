# YVK Design - текущий рабочий статус

Дата фиксации: 2026-06-27

Этот файл нужен как рабочая памятка перед дальнейшими правками, чтобы не возвращаться к уже решенным вопросам и не ломать готовые части сайта.

## Что уже сделано

- Сайт YVK Design собран как статический сайт с украинской и английской версиями.
- Основные страницы готовы: `index`, `services`, `projects`, `contact`.
- Карточки проектов генерируются из подготовленных папок проектов и имеют украинские/английские версии.
- Страница проекта использует единый шаблон: hero, информационный блок, планировки, галереи, lightbox, контактная форма.
- Навигация, мобильное меню, переключатель UA / EN, компактный футер и кнопка возврата наверх унифицированы.
- Форма заявки работает через Cloudflare Pages Function и Resend.
- Правильная логика отправки формы проверена:
  - `from`: `info@yvkdesign.com.ua`
  - `to`: `info@yvkdesign.com.ua`
  - email клиента используется только как `replyTo`
- Поле телефона может быть пустым. Имя, email, тип проекта и описание задачи обязательны.
- Кастомные тексты валидации работают на украинском и английском.
- Zoho Mail настроен как рабочая почта домена.
- Resend подключен для отправки заявок с сайта.
- Cloudflare Pages подключен к GitHub и домену `yvkdesign.com.ua`.
- Web Analytics Cloudflare включена.
- Сайт пока закрыт от индексации через `robots.txt`, потому что проект еще не завершен.

## Что не трогать без отдельного решения

- Не менять текущую логику форм, если нет конкретной ошибки.
- Не возвращать Brevo. Brevo был заменен на Resend.
- Не включать индексацию сайта, пока не будет принято отдельное решение.
- Не менять личный номер телефона сейчас. Позже он должен быть заменен на корпоративный во всех местах сразу.
- Не менять структуру готовых страниц и карточек проектов без отдельного согласования.
- Не подключать платные SEO-сервисы без явного решения.

## Ближайший план работ

1. Зафиксировать семантическую структуру сайта.
2. Создать рабочее семантическое ядро без платных сервисов:
   - украинская версия;
   - английская версия;
   - группы по страницам;
   - группы по типам проектов;
   - группы по услугам;
   - шаблоны SEO для будущих карточек проектов.
3. После согласования ядра подготовить SEO-правила для страниц:
   - title;
   - description;
   - H1/H2;
   - canonical;
   - Open Graph;
   - данные для sitemap.
4. Проверить, какие SEO-правки уже есть в коде, а какие нужно добавить.
5. Вносить SEO в сайт только после согласования структуры, без экспериментов с готовыми блоками.
6. После SEO перейти к финальной технической проверке:
   - формы;
   - ссылки;
   - UA / EN переключение;
   - мобильные версии;
   - страницы проектов;
   - отсутствие мусора в проекте.
7. Когда сайт будет готов к показу поисковикам, отдельно изменить `robots.txt` и открыть индексацию.

## Как добавлять новые проекты дальше

- Пользователь готовит папку проекта по согласованной структуре.
- Внутри проекта должны быть:
  - текстовый файл с описанием;
  - данные для UA и EN;
  - preview-изображения;
  - full-изображения;
  - планировки, если они нужны;
  - папки визуальных блоков с понятными названиями.
- После добавления папки генератор обновляет:
  - страницу `projects`;
  - блок проектов на главной;
  - страницу карточки проекта UA;
  - страницу карточки проекта EN.

## Важное правило дальнейшей работы

Перед крупной правкой сначала проверяем текущее состояние, затем меняем только нужный участок. Если часть сайта уже работает и пользователь подтвердил, что все нормально, не переделывать ее без причины.
