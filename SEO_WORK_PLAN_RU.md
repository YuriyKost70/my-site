# Рабочий SEO и технический план YVK Design

Этот документ объединяет два переданных SEO-документа в один практический план для текущего состояния сайта YVK Design. Он нужен, чтобы не возвращаться каждый раз к одному и тому же, не ломать уже настроенные части и двигаться по понятному порядку.

## 1. Главные правила работы

- Сайт еще в разработке, поэтому индексацию пока не открываем.
- `robots.txt` временно остается закрытым для поисковых систем.
- Основной домен сайта: `https://yvkdesign.com.ua/`.
- Технический адрес Cloudflare Pages используется только для проверки и разработки: `https://yvk-design.pages.dev/`.
- Ничего из уже подтвержденного не переделываем без явной причины.
- Формы, почту, хостинг, DNS и отправку заявок не трогаем, если нет новой ошибки.
- Не добавляем новые сервисы аналитики, рекламы или рассылок без отдельного решения.
- Все изменения по сайту делаем небольшими логичными шагами и фиксируем коммитами с понятным описанием.

## 2. Что уже сделано и считается рабочим

### Сайт и хостинг

- Сайт размещен на Cloudflare Pages.
- Домен `yvkdesign.com.ua` подключен и работает.
- Версия `pages.dev` остается технической.
- Украинская и английская версии сайта существуют.
- Основные страницы: Главная, Послуги, Проєкти, Контакти.
- Страницы проектов генерируются из папок проектов.

### Почта и формы

- Почта `info@yvkdesign.com.ua` работает через Zoho.
- Отправка форм работает через Resend.
- Brevo больше не используется.
- Правило отправки форм:
  - `from`: `YVK Design <info@yvkdesign.com.ua>`
  - `to`: `info@yvkdesign.com.ua`
  - email пользователя идет только в `reply_to`.
- Поле телефона может быть пустым.
- Поля имени, email, типа объекта и сообщения должны быть заполнены.
- Подсказки валидации должны быть на языке текущей версии страницы: украинский или английский.

### Аналитика

- Cloudflare Web Analytics подключена.
- DNS-статистика Cloudflare не равна реальным просмотрам сайта.
- Для реальных пользователей смотрим именно Web Analytics/RUM.

### SEO-база

- `sitemap.xml` есть.
- `robots.txt` есть, но пока намеренно закрывает сайт от индексации.
- Базовые title, description и canonical уже начали настраиваться.
- Финальную SEO-настройку делаем после стабилизации структуры и проектных карточек.

## 3. Что не делаем сейчас

- Не открываем сайт для индексации.
- Не меняем `robots.txt` на открытый режим.
- Не подключаем Google Search Console до финального решения об индексации.
- Не добавляем блог или статьи, пока не готова основная структура.
- Не используем фразу "ремонт під ключ", пока не подтверждено, что это реальная услуга.
- Не меняем текущий номер телефона, пока не будет корпоративный номер.
- Не переделываем формы, если они работают.
- Не возвращаем Brevo.
- Не делаем массовую SEO-перепись всех проектов, пока продолжается добавление проектных папок.

## 4. Правильная структура задач

### Этап 1. Зафиксировать текущее состояние

Цель: не начинать каждый раз с нуля.

- Проверить, что сайт открывается на основном домене.
- Проверить, что украинская и английская версии доступны.
- Проверить, что формы отправляют письма.
- Проверить, что проектные страницы открываются.
- Не исправлять то, что уже работает.

Статус: частично сделано, использовать только как контрольный чек перед важными изменениями.

### Этап 2. Семантическое ядро

Цель: определить, по каким запросам сайт должен находиться.

Основные направления:

- дизайн інтер'єру;
- дизайн екстер'єру;
- дизайн-проєкт квартири;
- дизайн-проєкт будинку;
- дизайн комерційних просторів;
- дизайн житлових інтер'єрів;
- консультація дизайнера;
- планувальне рішення;
- авторський супровід;
- дизайн у Сумах;
- дизайн інтер'єру Україна.

Не перегружаем классификацию. Для проектов достаточно основных типов:

- интерьер;
- экстерьер;
- жилой объект;
- бизнес/общественный объект;
- квартира;
- дом;
- коммерческое пространство.

Важно: слово "комерційний" не использовать как замену "проект за деньги". Для объектов бизнеса лучше использовать "простори для бізнесу", "громадські простори", "офіси", "кафе", "ресторани", "комерційні простори".

### Этап 3. Метаданные страниц

Цель: каждая страница должна иметь правильные title, description, canonical и языковые связи.

Проверить и привести к единому виду:

- `index.html` и `index-en.html`;
- `services.html` и `services-en.html`;
- `projects.html` и `projects-en.html`;
- `contact.html` и `contact-en.html`;
- все проектные страницы UA/EN.

Для каждой страницы нужны:

- уникальный `title`;
- уникальный `description`;
- `canonical` на основную версию этой страницы;
- `hreflang` для UA/EN пары;
- Open Graph title/description/image;
- корректный один `h1`.

### Этап 4. SEO-поля в генераторе проектов

Цель: новые карточки и страницы проектов должны получать SEO-данные автоматически.

В проектном описании должны быть поля:

- `slug`;
- `language`;
- `category`;
- `projectType`;
- `objectType`;
- `clientType`;
- `location`;
- `area`;
- `year`;
- `title`;
- `subtitle`;
- `shortDescription`;
- `fullDescription`;
- `seoTitle`;
- `seoDescription`;
- `seoKeywords`;
- `ogImage`;
- `galleryAltBase`.

Для украинской и английской версии данные должны быть разделены, но структура должна быть одинаковой.

Если английский текст пока пустой, украинская версия должна продолжать работать, а английская может быть заполнена позже.

### Этап 5. Изображения и alt-тексты

Цель: изображения должны помогать SEO и не ломать скорость.

Для каждого проекта:

- использовать preview-изображения для карточек и галерей;
- full-изображения использовать для большого просмотра;
- имена файлов должны быть стандартизированы;
- alt должен генерироваться из названия проекта, зоны и номера изображения;
- не использовать пустой или одинаковый alt для всех изображений.

Пример alt:

- `Дизайн інтер'єру квартири у Сумах, вітальня, YVK Design`
- `Apartment interior design, living room, YVK Design`

### Этап 6. Локальное SEO

Цель: сайт должен быть понятен как локальный профессиональный сайт студии дизайна.

После готовности сайта:

- создать или настроить Google Business Profile;
- указать единые данные NAP:
  - название;
  - телефон;
  - email;
  - город;
  - сайт;
- добавить реальные фото и примеры проектов;
- позже собрать отзывы клиентов;
- подключить Search Console;
- отправить sitemap.

### Этап 7. Техническая финальная проверка

Перед открытием индексации проверить:

- нет горизонтальной прокрутки на мобильных;
- формы работают на всех страницах;
- UA/EN переключение работает;
- все ссылки ведут на правильные страницы;
- все изображения загружаются;
- нет старых ссылок на Brevo;
- нет лишних DNS-записей;
- `robots.txt` готов к открытию;
- `sitemap.xml` содержит актуальные страницы;
- проектные страницы не дублируют друг друга некорректно;
- canonical и hreflang не конфликтуют;
- Cloudflare Pages показывает актуальный деплой.

### Этап 8. Открытие сайта для индексации

Делаем только после отдельного подтверждения.

Шаги:

- изменить `robots.txt` с закрытого на открытый;
- проверить `sitemap.xml`;
- подключить Google Search Console;
- подтвердить домен;
- отправить sitemap;
- проверить индексируемость главных страниц;
- через несколько дней проверить первые данные в Search Console.

## 6. Статусы задач

Используем простые статусы:

- `готово` - проверено и не трогаем без причины;
- `в работе` - сейчас делаем;
- `позже` - нужно, но не сейчас;
- `ждет данных` - нужна информация от Юрия;
- `не делать` - исключено из текущей стратегии.

## 7. Открытые вопросы

Ответы на эти вопросы нужны не срочно, но перед финальной SEO-настройкой:

- Будет ли услуга "ремонт під ключ" реально предлагаться?
- Какой корпоративный номер телефона ставим на сайт?
- Окончательный список типов проектов: интерьер, экстерьер, квартира, дом, бизнес-пространство?
- Будет ли Google Business Profile?
- Какие города кроме Сум нужно упоминать?
- Нужно ли продвигать только Сумы или всю Украину?
- Когда сайт можно открывать для индексации?

## 8. Порядок ближайших действий

1. Не трогать рабочие формы, Zoho, Resend и DNS без ошибки.
2. Завершить добавление текущих проектных папок.
3. Проверить генератор проектов на новом полном наборе папок.
4. Подготовить финальную структуру SEO-полей для проектов.
5. Составить финальное семантическое ядро UA/EN.
6. Обновить метаданные базовых страниц.
7. Обновить метаданные проектных страниц через генератор.
8. Проверить sitemap.
9. Только после подтверждения открыть robots.
10. Подключить Search Console и отправить sitemap.

## 9. Правило коммитов

Каждый значимый шаг фиксируем отдельным коммитом.

В сообщении коммита указывать:

- что изменено;
- какие страницы или файлы затронуты;
- что не менялось намеренно;
- что нужно проверить после деплоя.

Пример:

```text
Update SEO metadata plan

- Add unified SEO work plan for YVK Design
- Document current hosting, mail, forms and indexing state
- Define SEO stages, semantic core draft and project template fields
- Keep site code unchanged
```
